## Objective
Build **Vesk**, a compiler-first reactive UI framework where `.vsk` files compile to standard ESM with SSR, SSG, client hydration, islands, AOT event delegation, sub-component static extraction, streaming SSR, time-sliced hydration, `<Head>` metadata API.

## Important Details
- No regex anywhere in codegen. All tracked-name transforms done via AST walking (`zimmerframe`) + `esrap` serialize.
- `Expression` and `RuntimeStatement` IR nodes store ESTree AST node (`.ast`) + source reference (`.source`).
- `collectTrackedNames` returns `Map<name, {cellName, kind}>` where `kind` is `'virtual'` (auto-unwrap) or `'cell'` (raw cell). `&[name, c]`: `name` → read wraps `.get()`, write wraps `.set()`; `c` → write wraps `.set()`, reads stay identity.
- Single-element `&[name]` auto-unwraps reads everywhere. `bindValue(name)` with `&[name]` wrongly compiles to `bindValue(name.get())`. Users must use `&[name, c]` and write `bindValue(c)`.
- `bindValue`/`bindChecked`/`bindGroup` are auto-imported only when used (tree-shaken via AST scanning). React-style `<input value={name} onInput={e => name = e.target.value} />` is preferred and sufficient.
- `track` is always imported. `effect` imported only when component body is non-static. `getActiveComponent`/`setActiveComponent` always imported (for context). `batch`/`derived` imported only if referenced in source.
- Runtime import detection walks all IR node types recursively via `findBindingInIR()` + `astHasBinding()` (zimmerframe `walk` over ESTree).
- Children/slots: `{props.children}` or `{children}` in template creates `SlotNode`. `ComponentCall.children` stores children IR nodes. Server pre-renders children to HTML string. Client pre-renders to DocumentFragment. Hydrate mode skips children (already in DOM from SSR). `SlotNode` emits `__out.push(props.children || '')` on server, `if (props.children !== undefined && props.children !== null) parent.appendChild(props.children)` on client.
- SSR `<Head>` dedup via `headElementKey()`. Client `<Head>` dedup via `querySelector` find-or-create.
- Non-bubbling events use direct `el.addEventListener(...)`. Bubbling events use root delegation (`__evh_*` + `document.addEventListener` + `e.target.closest('[data-vsk-ev]')`).
- `ref={fn}` support: client emits `(fn)($el)`, SSR filters `ref` in all dynamic attr paths.
- `try/catch` in statement mode works on both server and client. `TryCatch` IR node stores `catchParamName`. Client codegen wraps DOM creation in try-catch; effects inside catch block are emitted inline (not deferred to function end) so they capture the error variable.
- Guard clause detection in `ir-generator.js` skips `if (cond) throw` — `ThrowStatement` consequents are not treated as guard clauses.
- All 321 tests run via `node --experimental-vm-modules <file>.test.js` (vitest broken by rollup native binary on Android/arm64). 208 parser/codegen/integration + 22 runtime tests pass.
- Context implemented as Ripple-style: `Context` class with `.get()` (walks `.p` parent chain looking for `.c` context map) and `.set()` (stores on current component's `.c`). `getActiveComponent()`/`setActiveComponent()` use internal mutable `{current}` object (not `export let`, which is read-only to importers). SSR fallback via `globalThis.__vesk_ctx`. Every component function body wrapped with `setActiveComponent({c: null, p: __prev})` / `try/finally` restore. 34-line runtime + ~2 lines of wrapper per component.
- Property-specific codegen: `PROPERTY_ATTRS` map defines element+attribute pairs that use direct property assignment (`el.value = expr`) instead of `setAttribute`. Applies to `input` (value/checked/indeterminate), `textarea` (value), `select` (value), `option` (selected), `progress` (value).
- `createResource(fn)` runtime: returns a callable `resource()` whose getter tracks a reactive cell. `.loading` and `.error` are reactive getters (Object.defineProperty). Starts `{loading: true}`, switches to `{loading: false, data}` when promise resolves.
- Keyed `key` prop: filtered from JSX attributes in `processJSXElement`, stored as `keyExpr` on `StaticNode` and `MapRegion` IR nodes.
