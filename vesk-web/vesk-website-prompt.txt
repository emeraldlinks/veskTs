Vesk — Website Design & Development Prompt

Design and build a modern, premium website for Vesk, a next-generation framework for building web and native applications with a compiler-first architecture.

The website should communicate that Vesk is not simply another JavaScript framework. It is a new approach to application development, designed around compile-time guarantees, native performance, developer experience, and a unified development model for web and native applications.

The experience should feel like the official website of a serious, ambitious developer platform that could eventually sit alongside ecosystems like Vercel, React, Kotlin, Swift, and modern developer infrastructure products.

DESIGN DIRECTION

Use the same overall design language as the Founders Forge website:

- Minimalist
- Premium
- Black and white foundation
- Strong typography
- High contrast
- Generous whitespace
- Subtle borders
- Sharp but elegant UI
- Modern developer-tool aesthetic
- Builder-first
- Technical without feeling intimidating
- Confident rather than overly promotional

Visual inspiration:
- Vercel
- Linear
- Stripe
- GitHub
- Raycast
- Framer
- Apple developer documentation
- Modern open-source developer tools

Do not copy these websites. Vesk should have its own visual identity.

The website should feel:

Precise. Fast. Intelligent. Experimental. Native.

Avoid generic SaaS gradients, excessive glassmorphism, stock illustrations, overly rounded cards, and conventional startup landing-page layouts.

HERO

or

2. INTERACTIVE CODE SHOWCASE

Make code a major part of the website.

Show a beautiful Vesk code editor interface.

Use actual Vesk syntax and Expression Mode. Do not represent Vesk simply as ordinary React/TSX.

Example direction:

component App {
  <main class="min-h-screen flex items-center justify-center">
    <h1>Hello, Vesk.</h1>
  </main>
}

Animate the code transforming into its compiled output.

The section should communicate:

Write modern Vesk code → Vesk understands it → Vesk compiles it → ship.

Use subtle syntax highlighting and animations.


3. WHY VESK

Create a strong section explaining the philosophy behind Vesk.

Potential themes:

Compiler First
Move important guarantees from runtime to build time.

One Development Model
Build applications using a consistent component and styling model across platforms.

Native Applications
Vesk Native compiles applications toward native Kotlin rather than simply wrapping a web application inside a WebView.

Developer Experience
Modern tooling, fast feedback loops, HMR, animations, Tailwind utilities, icons, and familiar component development.

Performance
The compiler should produce optimized output rather than carrying an unnecessary runtime abstraction.

Safety
If Vesk cannot safely preserve the semantics of your application, the compiler should fail the build rather than silently produce incorrect native behavior.

Show a visual device mockup containing a Vesk Native application.

Include:

- Fast development workflow

CTA:
Explore Vesk Native

UX & ANIMATION

Animations should be subtle, intentional, and technical.

Use:
- Smooth page transitions
- Scroll-based reveals
- Code transformations
- Terminal animations
- Hover states
- Subtle scale transitions
- Micro-interactions
- Animated compiler pipelines
- Device transitions for Vesk Native

Avoid:
- Excessive bouncing
- Distracting particles
- Huge gradient animations
- Overly flashy effects

The animation should communicate speed and precision.


RESPONSIVE DESIGN

The entire website must be:
- Mobile-first
- Fully responsive
- Excellent on phones
- Excellent on tablets
- Excellent on desktop
- Accessible
- Keyboard navigable
- Fast loading

On mobile, simplify complex diagrams and code demonstrations rather than simply shrinking them.


TECHNOLOGY

Use:
- TypeScript
- React
- Next.js
- Tailwind CSS
- shadcn/ui
- Framer Motion
- Lucide/Material icons where appropriate

Use clean, reusable components.

Structure the project so sections can easily be reused across the marketing website and documentation website.


VISUAL SYSTEM

Establish a consistent design system before implementing the pages.

Define:
- Typography scale
- Spacing system
- Border radius
- Shadows
- Border treatments
- Buttons
- Cards
- Code blocks
- Navigation
- Badges
- Tabs
- Terminal components
- Device mockups

Keep the visual system restrained.

Black and white should remain the foundation, with very limited accent usage.

Typography should do most of the visual work.


IMPORTANT PRODUCT POSITIONING

Do not describe Vesk as merely:
"another JavaScript framework."

Do not make the website sound like a generic React alternative.

The central message should be:

"Vesk is a compiler-first application framework."

The compiler is the product's defining technology.

Vesk Native should demonstrate the power of that architecture by allowing developers to move from a modern Vesk development experience toward native Kotlin applications.

The website should communicate that Vesk is building toward a larger vision:

"A unified, compiler-driven way to build modern applications."


OVERALL EXPERIENCE

The final website should feel like a product developers discover and immediately think:

"This is different."

It should feel technically credible enough for experienced developers while remaining understandable to someone discovering Vesk for the first time.

Prioritize:

Clarity → Identity → Technical credibility → Developer experience → Conversion

Do not overcrowd the page.

Every section should have a purpose.

The final result should feel like the official website of a serious developer platform with the ambition to become an important part of the modern application-development ecosystem.
