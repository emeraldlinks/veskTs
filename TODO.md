- [x] **BUG (compiler): `<div class="dot" />` does not mean `<div></div>` — it opened a div and swallowed every following sibling.** Found by reading SERVED markup (`curl /about`) rather than by writing a test, which is the only way it shows up. The HTML parser ignores the trailing slash on any non-void element, so a self-closed `<div>`/`<span>`/`<section>` opened an element whose children became everything after it, while the client's `createElement` built a real sibling — the served structure and the client structure disagreed before hydration even started. The SSR emitter emitted `/>` verbatim for any self-closed element. Now: void elements keep `/>`, anything inside `<svg>`/`<math>` keeps `/>` (self-closing IS part of their content model, and `<path />`/`<circle />` in a `.vsk` file depend on that), and everything else gets an explicit end tag. Blast radius in one real app was 9 sites across 6 files, including the login page's "or enter credentials" divider — where `<div class="flex-grow border-t" />` on both sides of a `<span>` meant the span, the second divider AND the entire login `<form>` were being parsed as children of the first divider.
- [x] **BUG (compiler): a dynamic attribute on a self-closed element was emitted AFTER the tag, so it was silently dropped.** The same emitter appended `__attr(...)` to the finished `<img />` string, producing `<img /> src="/x.png"` — the parser discards that, so `<div style={{ backgroundColor: accent }} />` served with **no `style` attribute at all** and the theme-swatch colour simply vanished. Same branch, same fix: attributes now land inside the open tag, before the `/>` or the explicit end tag. Tests: `server-codegen.test.ts` +10 covering both bugs across void/non-void/SVG/dynamic/static combinations; reverting the end-tag fix fails 5 and reverting the attribute fix fails 4, so both pins are real rather than decorative.
